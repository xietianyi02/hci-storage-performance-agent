# HCI 超融合存储性能专家 Agent

面向版本内性能问题排查、外部 POC 调优、预研性能调优的可扩展框架 Demo。

当前优先落地版本内排查：**固定环境、同一 fio 模型，与上一次测试对比**。默认页面直接选择批次和下降场景，用“概览、线程、CPU/NUMA、网络、时延/深度”标签查看差异。候选详情、评价和采集资料按需展开；其他场景通过顶部“页面”菜单进入。

“页面 → POC 调优”提供独立参数实验入口：针对当前设备、版本和 fio 模型保存基线配置，比较重复实验，按目标和时延约束选择候选参数。参数定义通过注册表扩展，设备档案与 fio 参数保留完整 JSON；结论限定在本任务范围。

每个定位或调优任务形成一个案例，同一案例可以执行多轮分析。页面展示场景输入、执行阶段、证据、根因假设、实验计划、对比结果、建议和专家评价，各轮运行独立保存。刷新页面或重启服务后可继续查看。

## 当前能力

- 版本测试批次导入、上一次同模型自动配对、fio 与线程/CPU/网络差异展示。
- 30 秒预热、60 秒正式测试的 3 秒分窗观测：同期 IOPS、具体线程落核、CPU/IPC 与 SMT 兄弟 CPU 负载；CPU/NUMA 展示全部逻辑 CPU 的同窗负载，缺失单独标记；各层时延、深度独立展示并预留接入。
- LangGraph 基于两次记录计算候选原因，保留依据、缺失证据、验证建议与专家评价。
- 固定环境档案、不可覆盖的测试批次、独立版本排查数据库；模拟与导入实测来源隔离。
- Linux 采集适配器与结构化导入契约，支持后续测试调度接入。
- POC 参数注册、设备 / fio 适用条件、任务建档、实验导入、重复结果对比及专家评价；支持 vhost 中断合并与 bdev 深度控制的明确模拟示例。
- 三类工作流入口与统一案例工作台。
- LangGraph 实际执行流程，SQLite 保存案例、审计记录及工作流 checkpoint。
- 实验前暂停，专家确认后恢复，保留确认和执行记录。
- 建议评价：已确认、已否定、待验证，记录评价理由与时间。
- 运行历史与记录导出；历史页面只读，建议统计覆盖各轮运行。
- 运营概览、知识库、流程模板、工具能力页面。
- 工作流、工具和推理服务适配器的扩展入口。

**演示边界：** 默认示例性能指标、采集结果和实验收益为模拟数据；版本排查与 POC 参数实验也可导入规范的实测记录，比较和分析来自所选数据。POC 示例参数没有真实环境绑定，不作为产品默认值或推荐配置。当前未连接集群、执行真实 fio 或调优真实设备，Linux 采集脚本尚未在用户集群运行。版本排查与 POC 分析不需要模型 API key；候选原因和参数建议由专家验证。旧案例可选模型适配器提供候选解释文本，不能直接执行环境命令或确认根因。

## 本地运行

需要 Python 3.11+、Node.js 20.19+ 或 22.12+，以及 pnpm。当前电脑已安装依赖并完成构建时，直接执行：

```powershell
.\scripts\start-demo.ps1
```

打开 <http://127.0.0.1:8000>。终端按 `Ctrl+C` 停止。

后台运行可使用 `.\scripts\start-demo.ps1 -Background`，之后使用 `.\scripts\stop-demo.ps1` 停止。停止服务保留案例数据。

首次在其他电脑安装：

```powershell
.\scripts\setup-demo.ps1
.\scripts\start-demo.ps1
```

前后端分别开发：

```powershell
# 仓库根目录
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000

# 另一个终端
cd frontend
pnpm dev
```

开发前端默认代理 `/api` 到后端 8000 端口。正式构建后的页面由 FastAPI 同源提供。

验证后端流程与持久化：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

## Demo 操作

默认打开“版本内排查”：

1. 选择本轮测试批次，页面自动寻找上一次同环境、同 fio 模型记录。首屏仅加载目录和指标概览；打开线程、CPU / NUMA 或时延 / 深度标签时，再按需读取所选场景的分窗采样。
2. 选择下降场景，在“线程”标签按 3 秒窗口观察同期 IOPS、具体线程 CPU/IPC/落核及 SMT 同核负载。默认“按进程”分组，区分主机、进程与 PID，并显示已采集线程的 CPU 合计；可切换“按 IO 流”，查看协议层 → IOR → 本地/远端数据分支 → 完成返回。切换视图保留所选轮次和区间，整轮线程池汇总同步分组。切到“CPU/NUMA”查看同窗全部逻辑 CPU，按主机和 NUMA 筛选、点击核查看负载。切换“时延/深度”保持同一区间，仅展示实际导入的层指标。旧批次缺少分窗或 CPU 清单时明确标记；整轮汇总按需展开。
3. 执行分析，查看由证据生成的候选原因、证据缺口和验证步骤。
4. 填写专家评价和依据，保存历次记录。
5. 使用“导入批次”导入规范 JSON；没有上一次记录时明确显示首次测试，不生成假基线。

采集与格式见 [Linux 采集说明](collectors/README.md)、[版本排查接口契约](docs/版本排查接口契约.md) 和 [排查思路](docs/版本内性能排查思路.md)。

POC 页面包含参数、实验对比和结论三个标签，可注册新参数、新建设备 / fio 调优任务、导入实验结果、分析参数及记录专家评价。方法与接入边界见 [POC 参数调优](docs/POC参数调优.md)。

顶部“页面”菜单保留原有 Demo：

1. 首页查看三类案例与建议评价统计。
2. 打开“案例记录”，查看示例案例的阶段、证据与实验结果。
3. 新建案例，选择场景、协议和 fio 模型，启动流程。
4. 查看根因候选与实验计划，在确认节点选择执行或拒绝模拟实验。
5. 查看对比结果，对建议填写评价；首页统计随评价更新。
6. 在“运行历史”切换查看各轮记录，或导出当前选中运行；历史页面只读。
7. 在“知识库”“工作流”“工具”查看当前知识边界与扩展位置。

## 结构

```text
backend/        FastAPI、LangGraph、案例存储、工作流与工具注册表
collectors/     Linux CPU/perf/IRQ 采集、fio 结果解析与批次合并
frontend/       React + TypeScript + Vite 页面
docs/           建设方案、扩展说明、验证记录
scripts/        安装和启动脚本
work/data/      运行时 SQLite 数据（忽略 Git）
work/           本地日志和 QA 临时文件（忽略 Git）
```

原始 [VM 到存储后端完整 IO 流.md](VM%20到存储后端完整%20IO%20流.md) 保留为产品知识来源。协议层与业务层以 IOR 为界；当前 POC 数据只存到本地和一个远端。

详细设计见 [建设方案](docs/建设方案.md) 与 [扩展指南](docs/扩展指南.md)。
