# POC 参数调优

POC 的设备、fio 模型不统一，重点是在当前设备和负载下寻找合适的参数配置。与版本内排查不同，跨 POC 不要求硬件一致；同一个参数实验任务内仍要固定设备、版本、协议和完整 fio 配置，才能判断参数的影响。

## 比较范围

每个任务（campaign）保存设备档案、版本、协议、完整 fio 参数、优化目标、时延约束、最少重复次数及基线参数配置。一个客户环境可创建多个 fio 模型任务；结论分别限定适用范围，不跨设备或不同 fio 模型计算统一收益率。

目标可选择 IOPS、带宽或平均时延，并可设置 p99 时延上限。未提供时延要求时，只说明目标指标收益及已观测代价，不称为整体最优。当前结果中的最佳候选仍需独立复测与专家评价，不保证未测试的参数组合。

## 参数注册

参数定义与调优页面分开，新增参数通过注册表进入，无需为每个参数新增页面。定义保存：

- 逻辑 ID、名称、所属组件、类型、单位、枚举或上下限。
- 适用协议、设备条件及 fio 条件。
- 需要观察的指标与解释。
- 真实环境适配器标识；尚未提供的绑定保持缺失。

任务创建时保存参数定义快照，实验保存完整参数集合。未知参数、类型不符、协议或适用条件不符、配置缺失均不参加比较，不静默补默认值。

首批两个示例来自用户描述：

| 参数 | 关注点 | 待产品补充 |
| --- | --- | --- |
| vhost 中断合并 | 不同 fio 模型的吞吐和时延变化，以及中断负载 | 实际参数名、单位、范围、读取 / 应用 / 回滚方式 |
| bdev 深度控制 | bdev 深度变化与 tierd 深度、磁盘时延和 IOPS 的关联 | 实际参数名、约束、深度 / 分层时延的测量方式 |

示例中的中断合并“档位”及性能数据仅用于演示，不是真实 vhost 参数单位、默认值或推荐值。bdev 深度过高可能造成下游排队，但单凭磁盘时延增加不能确认根因；需要固定其他参数，比较多个深度配置并复测。

## 实验与分析

1. 确定设备、fio、目标及基线参数，保存任务。
2. 先重复基线，再针对一个参数测试候选值；需要组合实验时记录完整配置及所有差异。
3. 导入每次实验的指标、原始产物引用和实际参数。保留无收益和反向收益记录。
4. LangGraph 校验任务范围、按参数配置归组、比较重复结果、生成候选报告。各组显示中位数、最小 / 最大值、重复数与约束判定。
5. 专家独立复测后确认或否定建议，记录依据、适用环境和 fio 范围。历次分析与评价保留。

时延约束检查每次实验的 p99；未知 p99 不视为满足约束。重复次数不足、基线不足或来源混用时不能给出有效推荐。观测关联和因果结论分开，Agent 不自动确认参数为根因。

## 接入边界

当前页面支持参数注册、任务建档、实验结果导入、数据分析和专家评价。POC 数据单独保存到 SQLite，既有版本测试记录和案例保留。模拟与实测隔离，原始产物仅保存引用，不读取任意本地文件。

fio 配置允许额外字段和不同模型格式；已识别的深度、任务数等字段校验类型与范围。任务与实验比较调用方提供的整个 fio 记录，不自动检查原始 jobfile 是否遗漏参数，也不证明设备实物始终未变；这些来源与一致性证据由后续采集适配器提供。

真实环境的设备识别、参数读取 / 应用 / 回滚、fio 执行及分层采集尚未接入。接入时围绕参数注册表及任务、实验契约提供专用适配器；不提供任意命令执行入口。设备条件与 fio 条件采用明确字段匹配，后续可增加能力识别和更丰富的条件判定。

多 fio 模型的综合配置选择、模型权重、自动探索策略及参数依赖优化后续扩展；当前先保留每个模型的实验和结论，避免跨模型泛化。
