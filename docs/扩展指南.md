# 扩展指南

## 当前版本内排查主线

默认入口使用 `backend/version_service.py`，按固定环境与完整 fio 模型寻找最近一次测试。`version_models.py` 校验导入结构，`version_metrics.py` 计算差异与单位 IO 成本，`version_store.py` 保存不可变批次、配对、分析事件与历次评价。旧三类案例使用下文的案例注册表，两套记录独立保存。

LangGraph 的实际节点为配对、fio 差异、CPU 证据、网络证据、候选整理、归档。`backend/version_rules.py` 中每条规则是独立函数，通过 `VersionRuleRegistry` 注册；增加 CPU、NUMA 或网络证据规则时不必改页面候选组件。例如：

```python
from backend.version_rules import VersionRule, default_version_rules

rules = default_version_rules()
rules.register(VersionRule("new_cpu_evidence", "cpu", evaluate_my_evidence, version="1.0"))
# evaluate_my_evidence(comparison) 返回含依据、缺口、验证步骤的候选列表。
# 在 VersionService(directory, rules=rules) 中使用该注册表。
```

规则只能给出待验证候选；当前筛查阈值是 IOPS 下降至少 5% 或平均时延上升至少 10%，后续应依据固定场景实测波动配置。规则版本写入分析记录。新增类别若需要独立工作流节点或新证据结构，还需扩展图和数据契约；不是任意命令插件。

同一配对重复分析保留评价。补录时间更近的上一轮时，生成新的配对与分析，旧记录保留；旧分析 ID 不能评价新配对。模拟与实测各自配对，环境定义和批次内容不能覆盖。

采集工具在 `collectors/`：进程发现、proc 解析、perf 命令、采集生命周期与批次合并分开。新增 vhost/iSCSI 前端、NVMe IRQ 或调度证据时，先明确来源、窗口、单位与缺失语义，再扩展适配器。原始文件作为引用归档；页面不读取任意本地路径。完整格式见 [接口契约](版本排查接口契约.md)，当前采集限制见 [采集说明](../collectors/README.md)。

## POC 参数实验

独立入口为 `#poc`，由 `backend/poc_models.py`、`poc_registry.py` 与 `poc_service.py` 管理参数定义、适用条件、固定任务范围和实验分析。参数及设备字段不写死在页面，JSON 注册和导入接口允许新增已确认的参数。真实参数绑定缺失时只允许保存与分析记录，没有集群执行能力。

任务保存定义快照、完整 fio 模型和基线参数。每次实验必须明确完整参数集合及相同设备、版本、协议、模型、来源；数据以参数配置归组，达到重复次数和逐次 p99 约束后才进入候选比较。LangGraph 执行校验、归组、比较、报告四个节点，SQLite 保留任务、实验、分析历史及专家评价。不能把某个设备 / fio 的候选配置写成通用推荐。

新增参数先声明类型、单位、范围、适用协议、设备条件、fio 条件及关注指标；实际参数名和读取 / 应用 / 回滚适配器由产品补齐。当前设备条件与 fio 条件采用明确字段匹配，自动识别能力、复杂依赖、自动参数探索及多模型综合目标留待后续接入。完整方法见 [POC 参数调优](POC参数调优.md)。

## 工作流

`backend/registry.py` 管理工作流、工具与分析策略注册表。版本排查、POC、预研保留独立的目标和关注点，当前共享统一场景输入、示例分析策略与实验计划。增加模式时注册新定义，通过 `tool_roles` 配置 fio、profile、experiment 对应工具，并指定分析策略；相应 API 返回定义元数据。

前端目前围绕三类业务提供入口。新增第四类模式还需更新 `frontend/src/types.ts` 的 `WorkflowId`、`ui.tsx` 的标签和图标、`NewCase.tsx` 的场景选项及 `App.tsx` 的筛选和首页入口。现有模板页可展示返回的阶段元数据，完整业务入口尚未全部由注册表动态生成。

扩展顺序建议：先补充输入契约、分析目标和结论标准，再接入节点策略与工具。工作流定义的版本号随行为变化更新。当前每轮保存工作流和工具元数据快照，以及策略和图版本号；工具与策略的执行代码在恢复时仍从当前注册表解析。因此恢复未完成运行应使用相同版本的实现，生产化需增加按版本路由和兼容性校验，避免中途升级改变恢复语义。

## 工具

模拟 fio、分层剖析和 A/B 实验工具是替换真实适配器的入口。真实适配器应输出可追溯的产物，而非只有一段文本：

- 标明来源是模拟、文件导入还是环境实测。
- 保存运行环境、时间窗口、fio 参数、版本、单位和重复次数。
- 给出原始产物引用与摘要；假设和建议引用这些证据 ID。
- 明确定义是否只读、是否需要确认、输入输出校验及失败语义。
- 调优工具提供作用范围、变更前后值、验证方法和回滚方法。
- 重试时使用运行 ID 与工具调用 ID 去重，避免重复调优或重复实验。

当前 Demo 不提供通用 SSH 或任意命令执行入口。真实集群接入时，需要围绕已明确的任务实现专用适配器。

## 推理适配器

`backend/providers.py` 定义推理接口，默认 `demo` 使用固定演示规则。可选兼容 Chat Completions 的服务通过环境变量配置：

```powershell
$env:HCI_LLM_PROVIDER = 'chat_completions'
$env:HCI_LLM_BASE_URL = 'https://your-approved-model-service.example/v1'
$env:HCI_LLM_MODEL = 'your-model-name'
$env:HCI_LLM_API_KEY = 'set-locally-do-not-commit'
```

API key 只在本地环境设置，不写入仓库。默认不会发起模型请求。启用该适配器后，案例标题、场景和证据会发送到所配置的模型服务，接入前应确认数据范围与服务用途。

此适配器当前只产生候选解释；结构化假设由配置的分析策略生成，工具调用由工作流配置驱动。模型自主策略选择、工具规划与同一轮中的多次实验仍需按专家流程逐步扩展。

## 知识与评价

架构知识和实测案例分开标记。原始 IO 文档属于架构路径证据，不是本次模拟性能指标的来源。模拟案例评价只用于验证运营链路，不能统计为真实业务收益。

知识页面和案例候选汇总已实现，工作流当前只记录静态知识引用 ID。自动检索架构正文、历史案例并用于推理尚未接入。模拟建议即使获得专家确认，也只作为知识候选展示；真实性能经验需要实测验证与入库审核。

建议评价保留审阅人、判定、理由与时间，评审记录追加保存；后续可以增加反证、复现实验与适用条件。每轮运行在独立运行表中保存证据、实验、报告与反馈，重跑不会覆盖旧轮次。历史页面只读；调用反馈 API 复核历史建议时必须显式传入对应 `run_id`，省略时更新当前运行。同一案例不同轮次可能复用 `R1` 等建议 ID，因此不能只凭建议 ID 定位历史建议。

运营统计与知识候选汇总枚举独立运行表。每条建议按 `(case_id, run_id, recommendation_id)` 区分，并按最新判定计数，不重复计算当前案例投影或历次评审事件；待验证不进入确认率分母。

## 生产化接口

本地单进程 Demo 使用 SQLite。生产化时依次补充：身份与权限、后台任务队列、多进程安全调度、PostgreSQL 案例与 checkpoint 存储、原始产物对象存储、事件订阅、环境互斥与回滚、真实数据的来源隔离与统计。
