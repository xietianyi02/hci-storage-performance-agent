# 版本排查实现契约 v1

固定环境，同一 fio 模型，本轮与时间上最近的上一轮配对。示例为 mock；采集导入为 measured。两类来源隔离，不相互配对。旧案例功能与数据保留。版本排查采用独立 SQLite 数据和真实 LangGraph 比较分析。

## 导入批次 Batch

```ts
type HostRole = 'guest' | 'local' | 'remote';
type Source = 'mock' | 'measured';
type Batch = {
  schema_version: 1; id: string; title: string; build: string; created_at: string;
  source: Source;
  environment: {id:string; label:string; description:string};
  changes: string[];
  scenarios: Snapshot[];
};
type Snapshot = {
  id:string; title:string; protocol:'nfs'|'vhost'|'iscsi';
  fio:{rw:string; bs:string; iodepth:number; numjobs:number; vm_count:number; ioengine:string; direct:number; [key:string]:unknown};
  window:{duration_s:number; started_at:string; completed_ios:number|null};
  metrics:{iops:number; bandwidth_mib_s:number; latency_ms:number; p99_ms:number|null};
  timeline:{offset_s:number; iops:number; latency_ms:number}[];
  threads:ThreadCapture[]; cpus:CpuCapture[]; network:NetworkCapture[];
  quality:string[]; artifacts:{kind:string; path:string; note:string}[];
};
type ThreadCapture = {
  host_role:HostRole; process_role:string; pool:string; branch:string;
  thread_count:number; cpu_time_ms:number|null; instructions:number|null; cycles:number|null;
  runqueue_wait_ms:number|null; context_switches:number|null; migrations:number|null;
  cpu_ids:number[]; allowed_cpu_ids:number[]; numa_nodes:number[]; memory_numa_nodes:number[];
  remote_access_pct:number|null; counting_ratio:number|null; counter_scope:string;
  top_functions:{name:string; samples_pct:number}[];
};
type CpuCapture = {
  host_role:HostRole; cpu_id:number; numa_node:number|null;
  user_pct:number; system_pct:number; irq_pct:number; softirq_pct:number; idle_pct:number;
  competitors:string[];
};
type NetworkCapture = {
  host_role:HostRole; interface:string; queue:string; irq_id:number|null;
  cpu_ids:number[]; allowed_cpu_ids:number[]; numa_node:number|null;
  irq_per_s:number|null; packets_per_s:number|null; drops:number|null; retransmits:number|null;
};
```

缺失计数为 null，不伪造 0。线程 CPU 时间为线程池总量，IPC 由线程池总计数相除。每 IO 成本分母使用同窗口 guest 完成数；只有整个 fio 测试的完成数而采样窗口不同，必须将该分母标为 null，单位 IO 成本不计算。CPU 百分比是每逻辑 CPU 的值，不将网络队列对应 CPU softirq 值称为该队列独占耗时。硬件性能计数范围不同或计数比例不足须提示不可直接比较。原始 perf 文件只记录引用，不通过 API 随意读取任意本地路径。

## API

- `GET /api/version/catalog`：返回轻量批次目录；保留 Batch 顶层字段，各场景仅含 `id/title/protocol/fio/window/metrics`，不含逐线程、逐 CPU 或分窗记录。
- `GET /api/version/batches/{batch_id}/scenarios`：返回本轮场景配对摘要，包含 `id/current_batch/previous_batch/current/previous/deltas`；current 和 previous 使用上述场景摘要字段，无上一轮时 previous 为 null。
- `GET /api/version/batches`：保留兼容的 `Batch[]` 完整记录接口，页面首屏不调用。
- `POST /api/version/batches`：导入一个 Batch，返回已保存 Batch；重复 ID 或同 environment.id 档案发生变化返回 409；结构错误 422。只导入数据，不执行命令。
- `GET /api/version/import-example`：返回可导入的 mock Batch 示例（生成新 id/时间，仍明确 mock）。
- `GET /api/version/comparisons/{batch_id}/{scenario_id}`：返回 Comparison。
- `POST /api/version/comparisons/{batch_id}/{scenario_id}/analyze`：执行 LangGraph 并返回 Comparison。相同不可变配对复用已保存分析，保留评价。
- `POST /api/version/comparisons/{batch_id}/{scenario_id}/feedback`：body `{analysis_id,candidate_id,verdict:'confirmed'|'rejected'|'pending',note,reviewer}`，返回 Comparison。评价只作用该配对，保留历次记录。

Comparison 的 GET、analyze 和 feedback 均支持 `?include_samples=false`，省略 current / previous 的 `sample_windows` 与 `cpu_inventory`，保留整轮汇总、质量、资料引用和分析评价。默认 true 保持完整记录兼容。页面先读取目录、场景摘要及选中场景的概览，打开线程、CPU / NUMA、时延 / 深度标签时再读取该配对的完整采样；同一页面缓存最多三对采样，各标签复用。未读取与真实缺失分开显示。

批次目录和场景摘要是原始不可变记录的派生索引，旧数据在服务启动时补齐，导入时同步保存。配对使用同来源、环境、完整 fio 和真实时间戳索引，避免反复读取全库采样；补录上一轮仍生成新的配对 ID，旧分析和评价保留。

```ts
type Derived = {cpu_pct:number|null; cpu_us_per_io:number|null; ipc:number|null; instructions_per_io:number|null; cycles_per_io:number|null};
type Comparison = {
  id:string; source:Source; environment:Batch['environment'];
  current_batch:Pick<Batch,'id'|'title'|'build'|'created_at'|'changes'>;
  previous_batch:Pick<Batch,'id'|'title'|'build'|'created_at'|'changes'>|null;
  current:Snapshot; previous:Snapshot|null;
  deltas:{iops_pct:number|null; latency_pct:number|null; p99_pct:number|null};
  threads:{key:string; before:ThreadCapture|null; after:ThreadCapture|null; derived_before:Derived|null; derived_after:Derived|null}[];
  cpus:{key:string; before:CpuCapture|null; after:CpuCapture|null}[];
  network:{key:string; before:NetworkCapture|null; after:NetworkCapture|null}[];
  quality:string[];
  analysis:Analysis|null;
};
type Analysis = {
  id:string; created_at:string; framework:'LangGraph';
  steps:{id:string; title:string; status:string}[];
  summary:string;
  candidates:{id:string; kind:string; title:string; priority:'high'|'medium';
    evidence:string[]; missing:string[]; validation:string[];
    verdict:'confirmed'|'rejected'|'pending'; note:string;
    review_history:{verdict:string; note:string; reviewer:string; timestamp:string}[];
  }[];
  events:{title:string; detail:string; timestamp:string}[];
};
```

配对按 source + environment.id + protocol + 完整规范 fio 参数确定，取当前批次之前最近的一条，不能只按 scenario.id。无上轮就明确首次记录，禁止填充假基线。分析规则按证据生成 CPU 成本、调度竞争、NUMA、网络处理等候选；数据不足或无下降时明确说明，不自动确认根因。

## Linux 采集扩展

三秒分窗新增可选 `Snapshot.observation` 与 `Snapshot.sample_windows`，具体线程与 CPU/SMT 同窗数据见 [三秒分窗观测契约](三秒分窗观测契约.md)。整轮摘要保持原有口径；旧批次没有这些字段时不补造数据。

`collectors/` 采集单机 guest/local/remote 观察包，实际 /proc/perf 结果保留原始文件与质量状态；合并工具将 guest fio 同窗口完成数、两端观察包转换为上述 Batch。不存在真实 perf/NUMA 数据时输出缺失。工具不连接 SSH，不运行调优命令；已有 fio 测试调度调用采集生命周期。

## 页面

根导航增加“版本内排查”，默认进入该页面；旧概览与三个场景页面保留。新页只有批次、fio 场景、上次/本次差异、候选与评价这一条主线。读写/高低深度示例同时包含 CPU 调度下降和远端 NIC 处理下降，避免固定猜 tierd。明确可筛选全部场景与仅下降场景。
