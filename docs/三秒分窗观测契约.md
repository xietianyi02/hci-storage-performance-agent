# 三秒分窗观测

这是版本批次 schema_version=1 的可选扩展。既有整轮结果与历史分析不覆盖，旧数据不补造分窗点。

## 时间口径

用户固定节奏为 30 秒预热、60 秒正式测试，每 3 秒一窗。预热 10 窗、正式测试 20 窗。区间 IOPS = 该区间 guest 实际完成 IO 数 / 实际秒数，代表区间吞吐，不称瞬时 IOPS。

`Snapshot.window` 仍表示正式测试的整轮统计窗口。新增 `observation` 表示含预热的观察起点与阶段时长；`sample_windows` 的起止偏移均相对此起点。预热与正式数据分别标记，旧 `timeline` 仍只使用正式测试的相对偏移。

```ts
type Observation = {
  started_at: string; // 含时区、包括预热的观察起点
  warmup_s: number;
  measurement_s: number;
  interval_s: number;
};
type IndividualThreadSample = {
  host_role: 'guest' | 'local' | 'remote';
  process_role: string; pool: string; branch: string;
  pid: number; tid: number; starttime_ticks: number;
  name: string; state: string;
  cpu_id: number | null; previous_cpu_id: number | null;
  allowed_cpu_ids: number[]; numa_node: number | null;
  cpu_pct: number | null;
  instructions: number | null; cycles: number | null;
  counting_ratio: number | null; counter_scope: string;
  migrations: number | null; runqueue_wait_ms: number | null;
};
type LayerSample = {
  layer: string; scope: string;
  latency_us: number | null;
  queue_depth: number | null;
};
type SampleWindow = {
  start_offset_s: number; end_offset_s: number;
  phase: 'warmup' | 'measurement';
  iops: number | null; completed_ios: number | null; latency_ms: number | null;
  threads: IndividualThreadSample[];
  cpus: CpuCapture[]; network: NetworkCapture[];
  layers: LayerSample[];
};
// Snapshot.observation?: Observation | null
// Snapshot.sample_windows?: SampleWindow[]
```

`CpuCapture` 增加可选 `smt_sibling_cpu_ids`（Linux 拓扑集合包括自己）、`core_id`、`socket_id`、`busy_pct`。界面排除当前 CPU 后展示 SMT 兄弟 CPU 及同主机、同区间的负载。未知拓扑和负载保持缺失。

## 观察与比较

每轮使用主机 / 本轮 run / PID / TID / starttime 区分具体线程生存期，避免 TID 重用串数据；跨轮仍按角色与线程池比较，不能认定两个版本的同数字 TID 是同一线程。

CPU 利用率使用实际区间的 CPU 时间差。CPU 落核是端点读到的最后执行位置，配合迁移次数观察；完整驻留或抢占原因需要后续调度跟踪。[Linux proc 文档](https://docs.kernel.org/filesystems/proc.html) 描述了这些进程与调度计数的来源。

IPC 使用对应区间的 instructions/cycles，要求计数配对、范围明确、覆盖率至少 90%；不能将全轮计数均分，也不能直接平均不同线程的 IPC。新生或退出线程、低覆盖、权限失败和窗口错位均保留缺失与质量说明。

页面默认仅观察正式测试，可选择包括预热。上轮与本轮采样间隔相同、预热和正式时长分别相差不超过 100ms 时，才尝试配对。正式区间减去各自预热时长后，端点偏差需分别不超过 `min(100ms, interval × 3%)`；仅双向唯一匹配有效。保留原始窗口与实际秒数，不重采样、不插值；超限、计划不一致或多解保持缺失。各层 `layers` 当前为空，待用户提供实际采集方法。

## 接入边界

Linux 本机采集读取 proc/sys/perf，外部测试调度器负责 fio 生命周期、guest 完成数、三端时钟同步与角色映射。Windows 可验证解析、合并、导入与界面，不能据此声称已完成真实集群采集或采集开销验证。示例分窗数据明确为 mock。
